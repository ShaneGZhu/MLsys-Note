Scheduling Mixed RL Rollouts Beyond Prefix Locality

按原论文顺序整理的中英对照精读文本：先读作者的问题陈述，再跟随公式、算法和实验结果，不把它改写成一份只讲结论的导读。

Zetao Hong, Song Yuan, Yuanhao Ding, et al.arXiv:2608.11152v1 · 11 Aug 2026Original paper / 原论文Local PDF / 本地 PDF

Abstract / 摘要

Abstract · 摘要

English

Modern reinforcement learning (RL) post-training pipelines for large language models increasingly combine rollout workloads across multiple domains and feedback paradigms. Prefix-aware routing improves inference efficiency through cache reuse and load balancing, but it does not control how heterogeneous rollout sessions compete for KV-cache capacity. When reinforcement learning with verifiable rewards (RLVR), reinforcement learning from human feedback (RLHF), and agentic rollouts share an asynchronous inference service, their distinct sequence structures, interaction patterns, and KV-residency times create substantially different serving demands. Rollout scheduling must account for this heterogeneity without distorting the workload mixture specified by the trainer.

We present MISA-T, a routing-layer admission policy for mixed rollout serving. MISA-T combines adaptive session admission, workload-aware KV-capacity allocation, and residency-time-aware KV accounting. In rollout-only ablations on Step3.7 and Qwen3.6-35B-A3B, MISA-T improves rollout throughput over a sweep-tuned cache-aware vLLM Router by 53.3% and 43.6%, respectively, while maintaining high prefix-cache hit rates. In a matched 50-iteration Step3.7 experiment, it increases rollout throughput by 35.6% and reduces mean iteration time by 22.8%, while keeping the consumed workload mixture close to the trainer target and achieving comparable task scores.

中文对照

现代大语言模型的强化学习后训练，越来越常把多个领域、多个反馈范式的 rollout 混在同一个生成服务里。感知前缀的路由可以依靠缓存复用和负载均衡提高推理效率，但它没有回答一个更基础的问题：异构 rollout session 如何竞争有限的 KV cache 容量？当 RLVR、RLHF 和 Agent rollout 共用异步推理服务时，它们不同的序列结构、交互方式和 KV 驻留时间，会产生明显不同的服务需求。调度器必须处理这种异构性，同时不能改变 trainer 规定的 workload 混合比例。

论文提出 MISA-T，一种位于路由层的混合 rollout 准入策略。它结合了自适应 session admission、按 workload 感知的 KV 容量分配，以及考虑驻留时间的 KV 记账。在固定 checkpoint 的实验中，相比经过 sweep 调参的 cache-aware vLLM Router，MISA-T 在 Step3.7 和 Qwen3.6-35B-A3B 上分别提高 rollout throughput 53.3% 和 43.6%。在匹配的 50 次 Step3.7 训练迭代中，rollout throughput 提高 35.6%，平均 iteration time 降低 22.8%，消耗的 workload mix 仍接近 trainer 目标，任务分数也相当。

一句话概括：prefix routing 决定“请求去哪儿”，MISA-T 额外决定“哪些新 session 现在有资格进入缓存工作集”。

1 Introduction

1 · Introduction / 引言

English

Modern RL post-training treats rollout generation as a distributed serving workload. A trainer releases prompts or agent tasks, the rollout layer translates them into model-generation requests, and a router assigns those requests to inference instances that reuse cached KV state whenever possible. PagedAttention, RadixAttention and distributed prefix-aware routing make prefix reuse a central efficiency objective.

The problem becomes harder when a rollout stream contains heterogeneous workloads. Multi-domain RL and multi-teacher on-policy distillation create shared inference pools where RLVR tends to have short prompts and long decode tails, RLHF has more balanced prompt and response lengths, and agentic trajectories require session continuity across repeated long-prefix calls and intervening tool execution. A cache miss on a later agent turn requires prefill of the accumulated interaction history.

中文对照

现代 RL 后训练可以看成一个分布式 serving workload：trainer 释放 prompt 或 agent task，rollout 层把它们转成模型请求，router 把请求分到不同推理实例，并尽量复用已经存在的 KV。PagedAttention、RadixAttention 和分布式 prefix-aware routing 让“前缀复用”成为 serving 的核心效率目标。

当一条 rollout 流包含异构 workload 时，问题会更难。多领域 RL 和多教师 on-policy distillation 会共用一个 inference pool：RLVR 往往是短输入、长 decode；RLHF 的输入和输出更均衡；Agent trajectory 则需要在多次长前缀调用之间保持 session continuity，中间还夹着工具执行。Agent 后续轮次一旦 cache miss，就必须重新 prefill 累积的交互历史。

English

The trainer controls staleness and maximum concurrency, while the router controls serving-side admission and instance selection. Choosing the instance with the largest cached prefix alone does not control how many sessions compete for KV capacity or how capacity should be shared across workloads. MISA-T therefore separates the trainer's mixture contract from the router's resource controller.

中文对照

Trainer 控制 policy staleness 和最大并发；router 控制服务侧准入和实例选择。只选择“缓存前缀最长”的实例，并不能限制有多少 session 同时争抢 KV，也不能决定不同 workload 如何分享容量。因此 MISA-T 把 trainer 的 mix contract 和 router 的 resource controller 分开：trainer 决定要采样什么，router 决定这些请求如何有序进入缓存。

Contributions / 贡献

1. Overload-aware session admission

根据观测到的 KV demand 和 overload pressure 推导动态 admission cap；超过 cap 的新 session 暂存并重试，已有 continuation 受到保护。

2. Workload-aware capacity allocation

按 RLVR、RLHF 和 agentic workload 的需求与 KV footprint 划分 protected admission capacity。

3. Residency-time-aware accounting

用 session 的 KV 驻留时间给需求加权，将 footprint allocation 扩展成 KV block-time accounting。

作者的边界声明：这是一项 routing-layer policy。它不改变 model execution、physical KV allocation、agent runtime，也不改变 trainer 设定的 workload distribution。

2 Background and Motivation

2 · Background and Motivation / 背景与动机

2.1 Rollout serving architecture / Rollout 服务架构

English

The trainer releases rollout tasks and bounds in-flight work through maximum-concurrency and policy-version staleness limits. Rollout workers translate tasks into model requests. A routing layer performs request admission and selects an inference instance. For agentic workloads, an agent server maintains the interaction loop and executes tool actions in an isolated sandbox. MISA-T needs only request metadata, runtime metrics and lightweight session-cache snapshots.

2.2 Mixed rollout generation / 混合 rollout 生成

English

A mixed stream can arise from joint multi-domain RL or from staged capability-integration pipelines. MOPD samples prompts from a multi-domain dataset, generates student rollouts, and routes each trajectory to its matching teacher. Similar integration patterns appear in MiMo-V2-Flash, Kimi K3, Nemotron 3 Ultra and Nemotron-Cascade 2. The trainer defines sampling distribution and rollout-group semantics; serving should improve efficiency without redefining them.

中文对照

混合流可能来自联合多领域 RL，也可能来自分阶段的能力整合流程。MOPD 从多领域数据集采样 prompt，生成 student rollout，再把每条 trajectory 路由到匹配的 teacher。MiMo-V2-Flash、Kimi K3、Nemotron 3 Ultra 和 Nemotron-Cascade 2 都体现了类似的能力整合模式。Trainer 定义 sampling distribution 和 rollout-group semantics；serving 层只能提高效率，不能重定义这些语义。

2.3 Prefix-aware routing / 前缀感知路由

English

Prefix-aware systems establish a common design: PagedAttention improves KV memory management; SGLang introduces RadixAttention; Preble balances distributed prefix reuse and load; DLPM/D2LPM combines reuse with fairness; k-LPM adds latency constraints. vLLM Router belongs to this family. Its cache-aware policy controls placement but not admission: it picks an instance for a request but does not limit how many new sessions enter it.

中文对照

这些系统共同建立了 prefix-aware load balancing：PagedAttention 改善 KV memory management；SGLang 用 RadixAttention 复用结构化调用的前缀；Preble 平衡分布式 prefix reuse 和负载；DLPM/D2LPM 把 reuse 与公平性结合；k-LPM 加入 latency constraint。vLLM Router 也属于这一路线。它控制 placement，却不控制 admission：会为请求选实例，但不会限制有多少新 session 进入该实例。

本文指出的缺口：已有 routing 主要优化 placement、load balancing 或 prefix reuse，没有按 workload-class 的 KV block-time demand 分配 admission capacity。Prefix hit rate 只能说明避免了多少 prefill，不能单独代表 rollout-serving efficiency。

2.5 Why placement-only routing falls short / 只做 placement 为什么失效

English

On Qwen3.6-35B-A3B, raising vLLM Router to a high-load concurrency ceiling reduces request throughput by 52.5%, effective prefill throughput by 57.3%, and decode throughput by 38.5% relative to its sweep-tuned operating point. Prefix-cache hit rate falls from 92.4% to 4.5%.

中文对照

在 Qwen3.6-35B-A3B 上，把 vLLM Router 提高到高负载 concurrency ceiling 后，相比 sweep 调出的 operating point，request throughput 降低 52.5%，effective prefill throughput 降低 57.3%，decode throughput 降低 38.5%，prefix-cache hit 从 92.4% 跌到 4.5%。

正反馈 loop：更多新 session 进入 → resident KV working set 膨胀 → reusable continuation 被驱逐 → 后续请求变 cold prefill → 队列和 session overlap 变长 → eviction pressure 进一步上升。

Global session cap 可以打断这个 loop，但仍把所有 session 当成同质对象。由于 workload 的 KV footprint 和 residency time 差异很大，同一个 session count 并不能决定 protected capacity 应如何分给不同类。作者报告：在同一 mixed stream 和 permissive concurrency ceiling 下，MISA-T 相比 class-agnostic Session Admission 在 Step3.7 上提高 37.3%，在 Qwen3.6-35B-A3B 上提高 20.4%。

2.6 Key insight and system challenges / 核心洞察与系统挑战

Admission is a KV commitment. / 准入是一项 KV 承诺。新 session 不只消耗当前容量，它还承诺未来的 KV 增长、后续 continuation，以及多轮之间的驻留时间。

在一个 scheduling epoch，某类有 Nb 个未完成 session，平均 footprint 为 k̄b、平均驻留时间为 Tb，那么它大约代表 Nbk̄bTb 的 block-time 工作量。由此产生三个挑战：在线 admission 不能依赖反复 static concurrency sweep；accounting 必须处理 workload heterogeneity；准入还要与 cache-aware placement 和 KV offloading 组合，而不是接管它们。

3 Problem Formulation

3 · Problem Formulation / 问题形式化

3.1 Trainer contract and routing decisions / Trainer 合约与路由决策

English

Let B be workload classes and W inference instances. A rollout unit is one trainer-counted sample; a prompt may fan out into grouped units. Each request inherits a workload class br, rollout-unit identity ur, session identity sr, and optional group identity gr. The trainer controls policy staleness, maximum concurrency and target mixture ρ. For each request, the router chooses πt(r) ∈ W ∪ {HOLD}: selecting an instance admits it; HOLD delays admission and periodically re-evaluates it.

中文对照

设 B 是 workload classes，W 是 inference instances。一个 rollout unit 是 trainer 计数的一条 sample；一个 prompt 可能 fan out 成多个有 group 关系的 unit。每个 request 都继承 workload class br、rollout-unit identity ur、session identity sr，以及可选的 group identity gr。Trainer 控制 policy staleness、maximum concurrency 和 target mixture ρ。Router 对每个 request 选择 πt(r) ∈ W ∪ {HOLD}：选实例意味着准入，HOLD 意味着延迟准入并周期性重评。

3.2 Prefix reuse and KV block-time demand / 前缀复用与 KV block-time

Estimated prefill cost / 估计 prefill 成本(1)
ĉr,w(t) = dw(t) + [Lr − Hr,w(t)] / μw(t)
English

The cost is queue delay plus the time to prefill only the non-reusable tokens. More prefix hit reduces the second term; a busy instance increases the first.

中文

成本 = 排队等待时间 + 重新 prefill 未命中 token 所需时间。命中的前缀越长，第二项越小；实例越忙，第一项越大。比如 10,000 token 中命中 8,000，prefill 速度 2,000 token/s，排队 0.4s，则成本约为 1.4s。

KV occupation is block-time / KV 占用是 block-time(2)
Zs = ∫ ks(t)dt ≈ k̄sTs
English

The integral is the area under the curve of retained KV blocks over time. For an agent, Ts includes tool-execution intervals between model turns because reusable KV remains resident.

中文

这是“KV blocks 随时间的曲线下面积”。Agent 在两次模型调用之间执行工具时，模型暂时不计算，但可复用 KV 仍驻留，所以这段时间也必须计入 Ts。例如 120 blocks 驻留 30s，就是 3,600 block·s。

Protected capacity constraint / 保护容量约束(3)
Σs∈Pw(t) k̃s(t) ≤ Cw,   ∀w∈W
English

The reserved footprint of protected sessions on each instance cannot exceed its protected KV budget Cw.

中文

每台实例上 protected sessions 的 reserved footprint 之和不能超过 Cw。Cw 是给 locality 保留的控制预算，不等于整块物理显存；物理 cache 和 offloading 仍由 serving layer 管理。

3.3 Scheduling objective under trainer contract / Trainer 合约下的调度目标

Rollout throughput / Rollout 吞吐(4)
Sπ(T) = 1 / T Σb∈B Nπb(T)
English

Nπb(T) counts complete class-b rollout samples delivered to the trainer. An agent trajectory is counted once only after all turns and tool interactions finish.

中文

Nπb(T) 是截至 T 完成并交付 trainer 的 b 类 sample 数。Agent trajectory 必须等所有轮次和工具交互完成才计 1，所以 rollout throughput 不等于 request RPM。

Long-run objective / 长期目标(5)
maxπ lim infT→∞ Sπ(T)   subject to   Qπb(T) = o(A(T)), ∀b∈B
English

Maximize long-run completed samples while ensuring no offered class is persistently delayed. The little-o condition means Qb(T)/A(T) tends to zero, not that backlog is always zero.

中文

最大化长期完成率，同时要求任何被提供的 workload class 都不能被持续饿住。o(A) 的意思是 Qb/A → 0，并不是积压必须始终为零。因为 Nb = Ab − Qb，只要 trainer 到达比例趋近 ρ、各类积压占比消失，完成的 mix 也会趋近 ρ。

Finite-run metric / 有限运行指标

DTV(p,q) = 1/2 ||p−q||1 measures the distance between completed and target mixtures.

直观解释

把每类比例差的绝对值相加再除以 2。目标 50/30/20、实际 46/33/21 时，DTV = (4+3+1)/2 = 4 个百分点，越接近 0 越好。

4.1 Adaptive session admission / 自适应 Session 准入

Continuation priority / Continuation 优先(6)
ADMIT(r,w) = { 1, if sr∈Ow∪Pw;   1, if |Ow|+|Pw| < Kw(t);   0, otherwise }
English

Ow is the observed active protected set. Pw contains sessions already admitted but not yet visible in the latest asynchronous snapshot. Existing sessions continue without consuming another cap slot; a new session needs headroom.

中文

Ow 是已观测的 active protected sessions；Pw 是已经放行、但还没出现在最新异步 snapshot 中的 pending sessions。Continuation 不重复消耗 cap；新 session 只有在 |O|+|P| 小于 K 时才能进入，否则 HOLD。把 pending 算进去，是为了避免两个 snapshot 之间连续超发。

Hold versus cold route / 等待缓存实例还是冷路由(7)
Δr + qhit − qcold < Hr / F
English

Holding for a cached instance is preferable when the extra waiting and queueing cost is smaller than the prefill time saved by reusing Hr tokens.

中文

左边是坚持 locality 的额外等待和排队代价；右边是复用 Hr 个 token 节省的 prefill 时间。只要左边更小，就值得 HOLD。若 H=40k、F=20k token/s，则缓存价值约 2s；即使额外等待 1.2s，仍应等待。

Relative prefix pressure / 相对前缀压力(8)
Gw(t) = max{0, h★w(t) − ĥw(t)}
English

The controller compares observed hit rate with a recent healthy achievable reference instead of using a universal fixed threshold. Confirmation and slope checks filter transient changes.

中文

压力是“健康参考命中率 − 当前命中率”，只有相对近期可达水平退化才产生压力。论文不硬编码 90% 之类的阈值，因为不同模型/workload 的可达水平不同；confirmation window 和 slope check 会过滤瞬时抖动。

Baseline cap 为 Kbasew(t)=⌊Cw/k̄w(t)⌋，其中 k̄ 来自已完成 session 长度的 moving window 和当前观测。Operational cap Kw(t) 不超过 baseline；当 prefix hit 确认下降或等待队列持续存在时，controller 暂时收缩 current cap，再逐步恢复。Overload pressure 是长度参考滞后时的快速修正，不是 cap 的常规来源。

4.2 Workload-aware session caps / 按 Workload 分配 Session Cap

Global cap 只控制 aggregate instance load，无法阻止 dominant class 占满全部新 session 的容量。MISA 为每个 instance w、workload class b 维护 Nw,b：active、pending、held 和 candidate session 都计入 demand ledger；held/candidate 尚未 admission 时不消耗 cap。每类的 k̄b 使用 conservative length priors、observed session blocks 和有界历史估计。

Spatial demand / 空间需求(9)
Sw,b = Nw,b k̄b
English

Number of unfinished session demands multiplied by the conservative resident-block estimate per session.

中文

本类未完成 session 数 × 单 session 的保守 resident blocks 估计。它只看空间，不看驻留多久。

Spatial quota and cap / 空间配额与 cap(10)
Mspacew,b = Cw · Sw,b / Σb′Sw,b′
Kspacew,b = max{1, ⌊Mspacew,b / k̄b⌋}
English

Protected blocks are split in proportion to spatial demand, then converted back to a session count. The max with 1 ensures every class has an entry point.

中文

先按各类空间需求占比分配 protected blocks，再除以该类单 session footprint 得到 cap。max{1,...} 保证每类至少能进入一个 session，避免完全饥饿。它是 soft quota，不是强制 trainer 采样比例。

4.3 KV-cache residency-time weighting / KV 驻留时间加权

Block-time proxy / Block-time 需求代理(11)
Rw,b = Sw,b T̂b = Nw,b k̄b T̂b
English

T̂b is the recent class-level duration during which useful KV remains attributable to class b. For a multi-turn agent it includes tool-execution gaps.

中文

T̂b 是该 class 最近观测到的“有用 KV 仍归属于它”的 session duration。多轮 Agent 的工具执行 gap 也算在内。它把空间需求提升为空间 × 时间的 block-time demand。

Estimated drain time / 估计 backlog 清空时间(12)
τw,b ≈ Nw,b k̄b T̂b / Mw,b
English

Backlog block-time divided by allocated parallel KV capacity estimates how long class b would take to drain. Allocating in proportion to R approximately equalizes τ across classes.

中文

分子是 backlog 的总 block-time，分母是获得的并行 KV block 容量，商可以理解为“这类 backlog 需要多久消化”。按 R 比例分配时，各类 τ 大致相等：长期占用更久的类会获得更大预算。

Time-weighted quota and cap / 时间加权配额与 cap(13)
Mtimew,b = Cw · Rw,b / Σb′Rw,b′
Ktimew,b = max{1, ⌊Mtimew,b / k̄b⌋}
English

Backlog, footprint and residency jointly determine the protected share. T̂ affects the budget share only; k̄ converts allocated blocks back to a session cap.

中文

积压越多、KV 越大、驻留越久，得到的 protected quota 越多；backlog 被消化后份额自然下降。注意 T̂ 只影响预算份额，最后仍用 k̄ 把 blocks 换回 session 数，避免单位混乱。例：Agent 与 RLVR 都需求 500 blocks，但驻留 20s/5s，则 block-time 比 4:1，1,000 blocks 大致按 800/200 分配。

4.4 Session-level cache accounting / Session 级 Cache 记账

English

The router receives two complementary cache views. A session snapshot records running and recently completed sessions, estimated total and cached KV blocks, lifecycle timestamps and instance capacity. Prefix location is tracked separately through block hashes from the inference engine. Longest matching prompt-block hash determines reusable prefix on each instance; eviction or reset removes the hash mapping.

中文对照

Router 使用两种互补视图：session snapshot 记录 running/recently completed sessions、total/cached KV blocks、生命周期时间戳和实例容量；prefix location 则由 inference engine 产生的 block hash 单独维护。对 incoming request，最长匹配的 prompt-block hash 决定各实例可复用的前缀；发生 eviction 或 cache reset 时删除映射。

4.5 Implementation summary / 实现摘要

MISA-T 可以是独立 scheduler，也可以与 serving gateway colocate。它先用 runtime metrics、session snapshots 和 workload metadata 过滤实例，之后让已有 cache-aware placement policy 在有 admission headroom 的实例中选择目标。它与模型执行、物理 cache 管理和 agent runtime 解耦。

6 Discussion

6 · Discussion / 讨论

Adaptive admission versus static concurrency

MISA-T retains the outer rollout-concurrency limit and does not seek a globally optimal outer limit. It reduces reliance on repeated static-concurrency searches as sequence lengths, residency patterns, serving demand and model checkpoints change.

自适应准入 vs. 静态并发

MISA-T 保留 outer rollout-concurrency limit，并不声称找到了全局最优的外层并发。它的目标是：当 sequence length、residency pattern、serving demand 或 checkpoint 变化时，不必反复做静态 concurrency sweep。

Compatibility with KV offloading

KV-offloading systems extend effective capacity by moving selected KV state outside GPU memory. MISA-T and offloading act at complementary layers: the router controls logical admission, while offloading determines whether reusable KV resides on GPU or CPU.

与 KV offloading 的关系

KV offloading 通过把选定 KV 移出 GPU 来扩大有效容量。MISA-T 和 offloading 位于互补层：router 控制 logical session admission，offloading 决定 reusable KV 物理上放在 GPU 还是 CPU。

本文的实际边界：方法假设请求带有正确 workload label，并依赖及时的 serving-state report。标签错误、snapshot 延迟或信息不完整，会让 KV-demand estimate 和 admission cap 暂时失准。实验只覆盖两个模型家族和有限硬件/trace，不能自动外推到所有拓扑和 workload shift。

7 Conclusion

7 · Conclusion / 结论

English

Mixed RL rollout serving requires more than prefix-aware instance selection. The routing layer must control how many sessions compete for KV capacity and allocate protected capacity across workloads with different KV footprints and residency times, while leaving the target workload mixture under trainer control. MISA-T addresses these requirements with adaptive session admission, workload-aware session caps and residency-time-aware KV accounting.

The authors report up to 53.3% and 43.6% rollout-throughput improvements over sweep-tuned vLLM Router on Step3.7 and Qwen3.6-35B-A3B, respectively; in matched Step3.7 training, throughput improves 35.6%, mean iteration time falls 22.8%, and mixture deviation decreases from 4.14 to 2.71 percentage points.

中文对照

混合 RL rollout serving 不能只做 prefix-aware instance selection。Routing layer 还必须控制有多少 session 竞争 KV 容量，并根据不同 workload 的 KV footprint 和 residency time 分配 protected capacity，同时把目标 workload mix 留在 trainer 手里。MISA-T 通过 adaptive session admission、workload-aware session cap 和 residency-time-aware KV accounting 来处理这些要求。

作者报告：相对 sweep-tuned vLLM Router，Step3.7 和 Qwen3.6-35B-A3B 的 rollout throughput 分别提高 53.3% 和 43.6%；匹配的 Step3.7 训练中，吞吐提高 35.6%，平均 iteration time 降低 22.8%，mix deviation 从 4.14 降到 2.71 个百分点。
